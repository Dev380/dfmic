## Project memory

- **RT while developing:** `tools/dfmic-rt` (sudo + `setpriv` ambient caps). `sudo -E` and `setcap` both fail: setuid/capability files put glibc in secure-execution mode, which drops `LD_LIBRARY_PATH`, and Slint's winit backend `dlopen`s libwayland/libEGL through it ("The wayland library could not be loaded").
- **"Is anything listening" = PipeWire links, not stream state.** `node.passive` made the exported node stay `running` with no consumers, so the stream never left `Streaming` and the daemon filtered 24/7 with the output meter live. Consumers are now counted from `Link` globals (`link.output.node` == our node id) in the registry listener. Never re-add `node.passive`.
- **Redraw trap (Slint 1.19):** any *animated* property the render reads makes `global_instant` a render dependency, so the window repaints at display rate for ever. The std ScrollView thumb does this; `scrollbar-policy: always-off` halved renders. Check with `SLINT_DEBUG_PERFORMANCE=refresh_lazy,console`: frames/s must never exceed the meter rate. Release builds only.
- **Device loss is data, not failure.** An unplugged/Bluetooth-dropped mic arrives as a stream `Error` *and* a core-level `ENOENT` ("target not found") — the core error is what actually killed the daemon. Both route through `is_missing_target()`/`note_capture_loss`, and no `bridge.set_source(..)?` may be fatal inside the event loop. Reproduce with a `pw-loopback` testmic; expect `filtering → no-device → idle`, alive.
- **AGC: gate on level, level the output.** `lsnr` cannot gate (quiet: median −9 dB). Gate = smoothed input ≥ floor + 12 dB, floor = min over 10 s. Target the *post*-suppression hop. Hold 600 ms, release 4 dB/s, boost 0.01/hop vs cut 0.05. Cap `gain ≤ −30 dBFS − floor` (WebRTC's `LimitGainByNoise`). −18 dBFS hop RMS ≈ −16 LUFS. Harness: `enhance --agc --agc-trace`.
- **PipeWire ring ownership:** `ring::Ring` is SPSC, so only the playback callback may move the read index of `output`/`monitor_output`. Third parties ask via `Shared::request_reprime()` (a counter the callback consumes), never `clear()`; `input` is the worker's. The buffer is `UnsafeCell<f32>` and `unsafe impl Sync` rests on that.
- **Idle cost:** the worker blocks on the `hop_ready` futex when nothing is listening; the daemon loop blocks on its request channel and every async source rings `control::wake()`. Idle = **0 wakeups/s**, but filtering is not idle: `ACTIVE_POLL` (200 ms) refreshes published diagnostics, else they freeze for the 30 s `STEADY_POLL`. `set_error`/`note_monitor_failure`/`note_capture_loss` must each `wake_loop()`. Off/no-model suspends capture.
- **OpenVINO host tensors:** `ov_tensor_create_from_host_ptr` keeps the pointer, so those buffers are written only via the raw pointer taken once in `Graph::allocate` (`in_ptr`/`state_ptr`); a later `&mut [f32]` invalidates it. `reset()` zeroes in place.
- **RT: rtkit, and refuse `module-rt`.** `LimitRTPRIO` is unusable from a user unit (the manager is at 0). rtkit promotes only the *calling* thread; needs priority < 21 (we use 18) and `RLIMIT_RTTIME <= 200000`. `module-rt` zeroes `RLIMIT_RTTIME` to 0/0 in every client, and a realtime thread with a zero budget is **SIGKILLed on its first slice of CPU** — looks like an OOM kill. Fix: `module.rt = "false"` in the context properties of `ContextRc::new` (its condition key). `rt.time.*` and `PIPEWIRE_CONFIG_DIR` do **not** help. Promote *after* the NPU compile: 0.5 s unblocked also exceeds the budget.
- **GUI renderer:** femtovg (hardware GL) repaints the whole window every frame at ~2.2 ms CPU, *area-independent*. Slint's software renderer is 3.5× cheaper only when GL is software; `select_renderer()` picks it for software GL, `SLINT_BACKEND` overrides. Software needs `software-renderer-path` (else `Path` icons vanish) and cannot transform items.
- **zbus:** `request_name`'s defaults let a second daemon take the name silently; `claim()` uses `DoNotQueue` alone, and the interface is exported *before* the name is taken — a name with nothing behind it makes clients block for ever.
