## Project memory

- **RT while developing:** use `tools/dfmic-rt` (sudo + `setpriv` ambient caps). `sudo -E` and `setcap` both fail because setuid/capability files put glibc in secure-execution mode, which drops `LD_LIBRARY_PATH` — and Slint's winit backend `dlopen`s libwayland/libEGL through it ("The wayland library could not be loaded").
- **GUI renderer:** femtovg (hardware GL) repaints the whole window every frame at ~2.2 ms CPU/frame, *area-independent*. Slint's software renderer is 3.5× cheaper only when GL is software; `select_renderer()` picks it for software GL, `SLINT_BACKEND` overrides. Software needs `software-renderer-path` (else `Path` icons vanish) and cannot transform items.
- **"Is anything listening" = PipeWire links, not stream state.** `node.passive` made the exported node stay `running` with no consumers, so the stream never left `Streaming` and the daemon filtered 24/7 with the output meter live. Consumers are now counted from `Link` globals (`link.output.node` == our node id) in the registry listener. Never re-add `node.passive`.
- **Redraw trap (Slint 1.19):** any *animated* property the render reads makes `global_instant` a render dependency, bumped every iteration — the window then repaints at the display rate forever. The std ScrollView scrollbar thumb does this; `scrollbar-policy: always-off` halved renders. Measure with `SLINT_DEBUG_PERFORMANCE=refresh_lazy,console`: frames/s must never exceed the meter rate. Judge on release builds only.
- **zbus name ownership:** `request_name`'s defaults (`AllowReplacement | ReplaceExisting`) let a second daemon silently take the name; `claim()` uses `DoNotQueue` alone, and the interface is exported *before* the name is taken — a name with nothing behind it makes clients block for ever.
- **AGC: gate on level, level the output.** `lsnr` cannot gate (quiet room: median −9 dB, ≥0 in 33% of hops). Gate = smoothed input ≥ floor + 12 dB, floor = min of the smoothed input over 10 s. Target on the *post*-suppression hop. Hold 600 ms, release 4 dB/s, boost 0.01/hop vs cut 0.05. Noise-ceiling cap `gain ≤ −30 dBFS − floor` so a mis-gated boost cannot amplify the room (WebRTC AGC2's `LimitGainByNoise`). −18 dBFS hop RMS ≈ −16 LUFS, pins the limiter on ~5% of speech hops. Harness: `enhance --agc --agc-trace`.
- **PipeWire ring ownership:** `ring::Ring` is SPSC, so only the playback callback may move the read index of `output`/`monitor_output`. Third parties ask via `Shared::request_reprime()` (a counter the callback consumes), never `clear()`; `input` is the worker's to clear. The buffer is `UnsafeCell<f32>` and `unsafe impl Sync` rests on that.
- **Idle cost:** the worker blocks on the `hop_ready` futex when nothing is listening. The daemon loop blocks on its request channel; every async source rings `control::wake()`. Idle = **0 wakeups/s**, but filtering is not idle: `ACTIVE_POLL` (200 ms) is the only thing refreshing published diagnostics, else they freeze for the 30 s `STEADY_POLL`. `set_error`/`note_monitor_failure`/`note_capture_loss` must each `wake_loop()`. Off/no-model suspends capture.
- **Device loss is data, not failure.** An unplugged/Bluetooth-dropped mic arrives as a stream `Error` *and* a core-level `ENOENT` ("target not found") — the core error is what actually killed the daemon. Both route through `is_missing_target()`/`note_capture_loss`, and no `bridge.set_source(..)?` may be fatal inside the event loop. Reproduce: `pw-loopback --capture-props='node.name=testmic media.class=Audio/Source' …`, `source testmic`, `pw-cat --target dfmic-source`, `pkill -f pw-loopback`; expect `filtering → no-device → idle`, daemon alive.
- **OpenVINO host tensors:** `ov_tensor_create_from_host_ptr` keeps the pointer, so those buffers are written only through the raw pointer taken once in `Graph::allocate` (`in_ptr`/`state_ptr`); a later `&mut [f32]` invalidates it. `Graph::reset()` zeroes in place, never reallocates.
